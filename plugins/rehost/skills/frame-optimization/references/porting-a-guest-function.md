# 게스트 함수 하나를 호스트로 옮기기 — 실제 절차

`frame-optimization` 이 "무엇을, 왜"라면 이 문서는 "어떻게"다.

## 1. 후크의 계약

실행 루프가 PC == 후크 주소일 때 호스트 함수를 부른다. 그 함수는 **둘 중 하나**를
한다:

```rust
fn host_xxx(&mut self) -> Result<bool, String> {
    // 인자를 읽는다
    // 감당 못 하면: return Ok(false);   ← CPU 상태를 하나도 건드리지 않은 채로
    // 감당하면: 일을 하고, r0 에 반환값을 넣고, PC = LR
    self.cpu.reg_set(Mode::User, 0, ret);
    let lr = self.cpu.reg_get(Mode::User, reg::LR);
    self.cpu.reg_set(Mode::User, reg::PC, lr);
    Ok(true)
}
```

핵심은 **거절 경로가 부작용이 없어야 한다**는 것. 인자를 다 읽고 나서 거절해도
좋지만, 게스트 메모리에 한 바이트라도 썼다면 거기서 되돌릴 수 없다. 검사를
먼저, 쓰기를 나중에.

## 2. 인자를 읽는 것이 1번 실수 지점

r0..r3 은 쉽다. **다섯 번째부터가 함정이다.**

스택 인자 N 의 위치는 프롤로그가 정한다:

```
push {r4..fp, lr}   →  sp -= 4 * 레지스터수
sub sp, sp, #0x48   →  sp -= 0x48
따라서 arg[N] = [sp + (pushed + subbed) + 4*N]
```

**같은 바이너리의 두 형제 함수가 서로 다른 값을 가진다.** 실제 사례:
`DrawScreen565` 는 `push 8 + sub 0x48` 이라 `[sp+0x68+4N]`, 그 `Ex` 판은
`sub 0x78` 이라 `[sp+0x98+4N]`. 표를 공유하면 거기서 틀린다.

기계적으로 뽑아라:

```bash
python ${CLAUDE_PLUGIN_ROOT}/scripts/disasm.py libgame.so TheFunc --frame
```

### 인자 **순서**도 형제 함수끼리 뒤집혀 있을 수 있다

실제 사례: 한쪽은 `arg[9]=alpha, arg[10]=level`, 다른 쪽은 `arg[12]=level,
arg[13]=alpha`. 이름이 비슷하다고 순서를 가정하지 말고 **호출자의 데이터 흐름으로
확인하라** — 호출자가 어느 스택 슬롯에서 읽어 어느 나가는 슬롯에 쓰는지를
`disasm.py` 로 따라가면 확정된다.

### 읽히지 않는 인자를 찾아 두면 이식이 작아진다

넘어오지만 **어떤 코드 경로도 읽지 않는** 인자가 흔하다. 해당 스택 슬롯을
grep 해서 0건이면 무시해도 된다. 소스 기하가 전부 구조체 하나에서 나오는데
호출자가 폭·높이를 따로 또 넘기는 식이다.

## 3. PC 상대 리터럴과 GOT — 테이블 주소는 정적으로 계산된다

PIC 코드는 전역을 이렇게 만진다:

```
ldr rG, [pc, #lit]      ; GOT 오프셋
add r4, pc, rL          ; GOT 베이스 = 여기 pc+8 + lit
ldr rP, [r4, rG]        ; 전역의 주소
ldr/str [rP, #field]    ; 실제 접근
```

호스트는 이 사슬을 **정적으로 계산해서** 테이블 주소를 얻을 수 있다:

```
GOT   = (리터럴로드주소 + 8) + u32[리터럴주소]
table = u32[GOT + u32[다른리터럴주소]]
```

`disasm.py` 가 이 사슬을 추적해서 `; GOT -> <심볼>` 주석을 달아 준다. 이게 없으면
PIC 함수는 끊기지 않는 `ldr` 의 벽이라 루프 카운터와 프레임버퍼 포인터를 구분할
수 없다.

**주의**: `add rX, pc, rY` 의 위치가 형제 함수끼리 다를 수 있다(한쪽은 진입+0x24,
한쪽은 진입+0x1c). 리터럴 표를 공유하면 여기서 틀린다.

## 4. 게스트 스크래치 전역을 되돌려 놓아라

폰트 스택처럼 **루프 카운터·커서·누산기를 전부 GOT 간접 전역**에 두는 함수가 있다.
호스트가 그 함수를 대신하면:

1. 진입할 때 그 전역들을 읽고,
2. 호스트 계산을 하고,
3. **종료 시점의 최종값을 되쓴다.**

그래야 관측 가능한 상태가 원본과 같다. 다른 게스트 코드가 그 전역을 나중에
읽는 경우가 실제로 있다.

## 5. 원본의 버그까지 재현하라 — "고치면" 틀린 것이다

실제로 만난 것들:

* **깨진 룩업 테이블 항목.** 표준 알고리즘의 표와 한 칸이 다르다. 그것은 대체
  구현이 아니라 **원본에 박힌 오타**이고, 표준 표를 하드코딩하면 세이브가 깨진다.
  → **테이블을 하드코딩하지 말고 게스트 메모리에서 심볼 이름으로 읽어라.**
* **빠진 최종 스왑.** 알고리즘이 교과서와 한 단계 다르다. 자기 역연산이 자기
  정연산을 되돌리므로 내부적으로는 일관되지만 표준이 아니다.
* **절삭 나눗셈으로 얻은 블록 수.** `len/8` 이라 꼬리 `len%8` 바이트가 처리되지
  않고 남는다. 올림하면 **모든 데이터의 꼬리를 덮어쓴다.**
  (`add r3,r8,#7 / cmp r8,#0 / movlt r8,r3 / asr r1,r8,#3` 은 `(len+7)/8` 이
  아니라 **부호 있는 8로 나누기 관용구**다. `+7` 은 음수 보정일 뿐이다.)
* **비대칭 블렌드 가중치.** 한 채널만 `+1` 이 없다. 출하된 비대칭이다.
* **10.10 고정소수 스텝의 `+1`** 때문에 마지막 소스 인덱스가 소스 끝을 넘는다.
  게스트가 행 뒤 1바이트를 읽으므로 **호스트도 그 바이트를 범위에 넣어야 한다.**
  클램프하면 틀린다.
* **버퍼의 자기 pitch 를 무시하고 소스 폭으로 채우는 것.**

원칙: 화면은 픽셀 단위로 같아야 하므로, "개선"은 정의상 회귀다.

## 6. 자기 검증 — 게스트 자신에게 물어보고 나서 쓴다

데이터 무결성이 걸린 것(세이브 암호화 등)은 A/B 만으로 부족하다. 부팅 때
**게스트의 원래 함수를 `Vm::call` 로 직접 돌려서** 호스트 결과와 대조하라.

```rust
// 부팅 끝 (키 스케줄이 준비된 뒤)
let ok = selftest_roundtrip(&mut vm);   // 양방향 모두
if !ok { log::error!(...); disable_this_patch(); }   // 그 방향은 해석기에 맡긴다
```

설계 포인트:

* **양방향 모두** 검사한다(암호화/복호화, 압축/해제).
* **탐침 크기를 확률로 정하라.** 데이터 의존 분기가 없는 알고리즘이면 한 번의
  왕복이 전체 상태공간을 지나가지만, **깨진 테이블 항목 하나**는 확률적으로만
  잡힌다. 표 항목 하나가 64분의 1 확률로 발동한다면 8블록은 13% 확률로 통째로
  놓치고 16블록이면 약 1.8%다. 크기를 그 계산으로 정하라.
* 비용은 부팅 때 한 번, 백만 명령 수준(기기 20 ms)이면 충분히 싸다.
* **검사가 실제로 작동하는지도 확인하라.** 게스트 메모리의 테이블 한 칸을 일부러
  표준값으로 바꿔 놓고 검사가 불일치를 잡는지 본다. 잡지 못하면 그 검사는 장식이다.
* 불일치 로그는 **첫 불일치 블록**을 찍어라. 안 그러면 "같은 바이트가 다르다"로
  읽히는 출력이 나온다(첫 블록이 우연히 일치하는 경우).
* 검사가 건드리는 것은 **호스트가 할당한 버퍼뿐**이어야 한다. 방향 플래그가
  래퍼에 있다면 래퍼를 부르지 마라.

## 7. 함수 중간에 후크를 걸어야 할 때

진입점이 아니라 함수 **중간의 특정 명령**에 걸어야 하는 경우가 있다(→
`guest-behavior-patching` 스킬이 이 주제를 자세히 다룬다). 성능 목적이라도
규칙은 같다:

**그 주소의 명령어 워드를 설치 시점에 확인하고, 다르면 설치하지 않는다.**

```rust
const SITE_WORD: u32 = 0xe59d_201c;   // ldr r2, [sp, #0x1c]
if mem.r32(addr) != SITE_WORD { return None; }   // 다르게 빌드된 게스트
```

스택 슬롯 오프셋 같은 것은 빌드가 바뀌면 완전히 다른 것을 가리키게 되고,
그때 조용히 틀리는 것보다 설치가 안 되는 편이 백 배 낫다.

## 8. 이식이 생각보다 작아지는 이유 — 호출자가 이미 일을 해 놨다

블리터를 열기 전에 **호출자를 먼저 읽어라.** 자주 있는 일:

* 호출자가 이미 클립 사각형과 교차시키고, 비면 조기 반환하고, 넘치는 만큼을
  `dx/dy/w/h/sx/sy` 에 되접은 뒤 디스패치한다.
* 그러면 블리터 본체는 **클립 전역을 아예 읽지 않는다.** 픽셀당 클립 검사도,
  배율도, 누산기도 없는 1:1 사각형이 된다.
* 확인 방법: 클립 전역을 담는 GOT 슬롯이 그 함수의 리터럴 풀에 있는지 본다.
  없으면 안 읽는 것이다.

반대로 이걸 모르고 클립 로직을 다 옮기면 두 배로 일하고 두 배로 틀릴 곳이 생긴다.

## 9. 공유할 수 있는 것은 공유하라 — 증거까지 물려받는다

형제 함수 넷이 **바이트 단위로 같은 블렌드 파이프라인**을 들고 있는 일이 흔하다
(레지스터 배치만 다름). 호스트에서 하나로 뽑아 공유하면 코드가 짧아지는 것보다
중요한 이득이 있다: **두 번째 이식이 첫 번째 이식의 A/B 증거를 그대로
물려받는다.**

확인은 기계적으로 — 두 함수의 해당 구간을 `disasm.py` 로 뽑아 나란히 놓고
산술이 같은지 본다.
